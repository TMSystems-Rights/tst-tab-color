### 課題2（今セッション完了済み）

**現象**: ホバー時・通常時ともに、開閉トグル（`.twisty`）と閉じるボタン（`.closebox`）が指定色で描画されない。

**原因**: TST の `.twisty` / `.closebox::after` は `color` ではなく以下で色を制御している（TST 公式ソース確認済み）:
- `.twisty`: `fill: var(--tab-text)` + SVG コンテキストフィル
- `.closebox::after`: `background: var(--tab-text)` + CSS マスク

**修正**: `BuildCss` において通常時・ホバー/アクティブ時ともに CSS 変数 `--tab-text` を書き換える方式に変更。これにより `.label`（color）/ `.twisty`（fill/background）/ `.closebox::after`（background）へ一括伝播。`.label` には `color` も冗長指定し、TST 側の特異度に負けた場合の保険とする。

動作確認済み（通常時・ホバー・アクティブすべて OK）。関連コード：
- [src/background/background.js](../src/background/background.js) の `TMS_BACKGROUND.Tst.BuildCss`
- [docs/020_機能設計書.md §6.2](./020_機能設計書.md#62-css-生成ロジック) に反映済み

## 課題1：全タブ一括適用のパフォーマンス改善（未着手）

### 現象

1,992 タブ環境で全タブにルール適用すると **1 分 38 秒** かかる。処理は同期的に `await TMS_BACKGROUND.Tst.SendMessage` を1タブずつ直列実行している。

該当コード：[src/background/background.js](../src/background/background.js) の `TMS_BACKGROUND.Tst.ApplyRulesToAllTabs`（ファイル後半、`for (const tab of tabs) { await TMS_BACKGROUND.Tst.ApplyRuleToTab(tab); ... }` の箇所）

1タブあたり `ApplyRuleToTab` 内で `ClearTabState`（`remove-tab-state`）+ マッチ時は `add-tab-state` の最低 1〜2 往復が発生している。

### ユーザー提案の対策方針

- 同期（await）を外して非同期化する
- TST のメッセージキューを溢れさせないためスロットリングを入れる（例: 同時実行数制限 / バッチ送信）

### 実装検討ポイント（提案ベース、次セッションで再確認）

1. **バッチ API の活用**
   TST の `add-tab-state` / `remove-tab-state` は `tabs` に配列を受け付けるため、「同一クラス名を付与すべきタブをまとめて1メッセージ」にできる可能性がある。ルール評価結果をルール別にバケット化してから各ルール1回の送信にまとめられれば、往復回数を rules 数＋1 程度まで圧縮可能（要 TST API 仕様確認）。

2. **並列実行＋同時実行数制限**
   `Promise.all` で一斉発射するとキュー爆発の恐れがあるため、同時実行数 N（例: 10〜30）でスロットリングするワーカー方式が妥当。

3. **ClearTabState の削減**
   現状は「起動時に全タブ分の remove-tab-state を総当たり」している。初回適用時は旧クラスが付いていないケースが多いので、`count` 判定等でスキップ可能な経路がないか検討。

4. **register-self の先行化**
   `ApplyRulesToAllTabs` の完了を待たずに他処理を進められるか（起動直後 UI 応答性）。

5. **進捗ログの扱い**
   現行の `console.log('★★★★★進捗…', ...)` は 100 タブごとに出力。並列化後もこれを維持するか、計測用途のみで外すかを決める。

### 測定・検証方法

- 1,992 タブ環境で `ApplyRulesToAllTabs` 開始〜終了の経過時間を `performance.now()` 等で計測
- 改善前後の所要時間比較
- TST サイドバーのタブ色適用が取りこぼしなく完了しているかを目視確認
- ルール並べ替え・ルール追加・ルール削除後の全タブ再適用でも退行しないことを確認

## コード構造の要点（引継ぎ時の迷い防止）

### 名前空間

- `TMS_COMMON` ([src/common/common.js](../src/common/common.js)): 共通ユーティリティ、定数（`TST_ID`, `CSS_CLASS_PREFIX` 等）、色関連（`InvertColor` 等）、ルール評価（`MatchRule`）
- `TMS_BACKGROUND` ([src/background/background.js](../src/background/background.js)): バックグラウンド処理
- `TMS_OPTIONS` ([src/options/options.js](../src/options/options.js)): オプションページ

DeepFreeze + `Object.seal`/`freeze` で保護されている。

### TST 連携

- `TST_ID = 'treestyletab@piro.sakura.ne.jp'`
- メッセージ送信は `TMS_BACKGROUND.Tst.SendMessage` でラップ（TST 未インストール時のエラーを握りつぶす）
- CSS 注入は `register-self` の `style` プロパティ経由（`BuildCss` で生成）
- タブへのクラス付与は `add-tab-state` / `remove-tab-state`

### 重要制約

- TST の要素は `.twisty` / `.closebox` / `.label` / `.background` の互換クラスで CSS 指定可能（公式ソースで確認済み、後方互換）
- `.twisty` / `.closebox::after` は `color` プロパティに反応しないため `--tab-text` 変数または `fill`/`background` 直接指定が必要
- 背景色は `.tab` ではなく内側の `.background` に当てる（子階層インデント領域に漏れるのを防ぐため）
