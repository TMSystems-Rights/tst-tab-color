## 1. 実装方針

- 既存拡張機能（tst-multi-function-exporter）のフォルダ構成・コーディング規約を踏襲する
- ビルドツールなし（Vanilla JS）。ファイルをそのまま Firefox に読み込む形式
- 実装はフェーズ単位で進め、各フェーズ末に Firefox で動作確認を行う
- コーディングルール（`docs/100_コーディングルール.md`）に従い、実装完了後に ESLint でチェックする

## 4. ファイル実装順序

依存関係を考慮した推奨実装順序。

```
1. package.json
2. eslint.config.mjs
3. .gitignore / .code-workspace
4. src/manifest.json
5. src/lib/jquery.min.js         ← npm install jquery 後に node_modules からコピー
6. src/common/common.js          ← TMS_BACKGROUND が依存
7. src/background/background.js  ← コア機能
8. src/_locales/ja/messages.json
9. src/_locales/en/messages.json
10. src/options/options.html     ← i18nキーを確認しながら作成
11. src/options/options.css
12. src/options/options.js
```

## 6. 未検討事項・リスク

| # | 項目 | 内容 | 対応方針 |
|---|------|------|----------|
| R-01 | TST のタブ DOM セレクタ | `.tab` / `.label` セレクタは TST の内部実装に依存する。TST バージョンアップで変わる可能性あり | TST の公開 API と GitHub リリースノートを監視。変更時は CSS を修正して再配布 |
| R-02 | Firefox アドオン審査 | jQuery の使用が審査対象になる可能性 | CDN は使用しない。`npm install jquery` で取得した `jquery.min.js` を `src/lib/` にコピーして同梱し、`options.html` から相対パスで読み込む |
| R-03 | ReDoS 対策 | 悪意ある正規表現（例：`(a+)+`）によるパフォーマンス低下 | オプションページのバリデーションで明らかに危険なパターンを検出する仕組みを検討（Phase 6 で評価） |
| R-04 | storage.sync 容量制限 | Firefox の `storage.sync` は 100KB / アイテムあたり 8KB の制限あり | ルール上限 100 件であれば超過しないと想定。初期バージョンでは監視のみ |
