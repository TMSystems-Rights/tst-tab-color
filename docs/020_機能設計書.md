## 1. システム全体構成

```
┌─────────────────────────────────────────────────────┐
│  Firefox ブラウザ                                    │
│                                                     │
│  ┌─────────────────┐   sendMessage    ┌──────────┐  │

│  │       │storage  │                               │
│  │       ▼         │                               │
│  │  storage.sync   │                               │
│  │       ▲         │                               │
│  │       │         │                               │

│  └─────────────────┘                               │
└─────────────────────────────────────────────────────┘
```

### 処理の流れ（概要）

1. 拡張機能起動 → TST に `register-self` で登録し CSS を注入
2. `storage.sync` からルール一覧を読み込む
3. 全タブの URL を評価し、マッチしたルールの CSS クラスを `add-tab-state` で付与
4. タブ作成・URL 変更イベントを受信 → 同様に評価・付与
5. ユーザーがオプションページでルールを編集 → `storage.sync` 更新 → バックグラウンドが検知 → 再評価・再適用

## 4. データモデル

### 4.1 ルールオブジェクト

```javascript
/**
 * @typedef {Object} TcRule
 * @property {string}            id              - UUID（ルール識別子）
 * @property {string}            pattern         - URLパターン文字列
 * @property {'prefix'|'regexp'} patternType     - パターン種別
 * @property {string}            fontFamily      - font-family 値（空文字 = 未指定）
 * @property {string}            fontColor       - color 値（空文字 = 未指定、例: "#ffffff"）
 * @property {string}            backgroundColor - background-color 値（空文字 = 未指定）
 */
```

### 4.2 storage.sync スキーマ

| キー | 型 | 内容 |
|------|----|------|
| `rules` | `TcRule[]` | ルール一覧（配列の順序 = 優先順位。index 0 が最高優先） |

### 4.3 storage.local スキーマ（Phase 8 追加）

オプションページの見た目に関する設定（端末ローカルの個人設定）は `storage.local` に保存する。
`storage.sync` は複数端末間で同期されるため、端末ごとの好みが混ざらないよう保管先を分ける。

| キー | 型 | 既定値 | 内容 |
|------|----|--------|------|
| `theme` | `'dark' \| 'light'` | `'dark'` | オプションページのテーマ設定 |

## 6. TST API 連携設計

### 6.1 register-self（起動時・ルール変更時）

```javascript
browser.runtime.sendMessage(TMS_COMMON.Const.TST_ID, {
    type:           'register-self',
    name:           browser.runtime.getManifest().name,
    icons:          browser.runtime.getManifest().icons,
    listeningTypes: ['ready'],
    style:          TMS_BACKGROUND.Tst.BuildCss(rules)
});
```

### 6.2 CSS 生成ロジック

ルール配列からインデックスベースの CSS クラスを動的生成する。
ブランク項目はプロパティを出力しない。

```
rules[0] → .tab.tm-rule-0 .background { background-color: #ff0000; }
           .tab.tm-rule-0 .label      { color: #ffffff; font-family: Arial; }
           .tab.tm-rule-0:hover .background,
           .tab.tm-rule-0.active .background { background-color: #00ffff; }   /* 反転色 */
           .tab.tm-rule-0:hover .label,
           .tab.tm-rule-0.active .label      { color: #000000; }              /* 反転色 */
rules[1] → .tab.tm-rule-1 .background { background-color: #0000ff; }
           .tab.tm-rule-1:hover .background,
           .tab.tm-rule-1.active .background { background-color: #ffff00; }
```

**セレクタ対象**

| スタイル | 通常時セレクタ | :hover / .active 時セレクタ | CSS プロパティ |
|----------|----------------|------------------------------|----------------|
| 背景色 | `.tab.tm-rule-{n} .background` | `.tab.tm-rule-{n}:hover .background, .tab.tm-rule-{n}.active .background` | `background-color` |
| フォント色 | `.tab.tm-rule-{n} .label` | `.tab.tm-rule-{n}:hover .label, .tab.tm-rule-{n}.active .label` | `color` |
| フォント | `.tab.tm-rule-{n} .label` | （反転なし） | `font-family` |

**背景色のセレクタ設計ポイント（Phase 8）**

- 背景色は親 `.tab` ではなく内側の `.background` 要素に適用する。子階層タブのインデント領域（左側の余白）にまで背景が漏れるのを防ぐため（Phase 8 Bug 1 対応）。
- フォント色も TST ビルトインの `:hover` / `.active` 既定スタイル（通常の淡色ハイライト）に上書きされないよう、`:hover` / `.active` 時の `.label` への色指定でオーバーライドする。

**:hover / :active 反転オーバーライドの出力方針（Case C）**

- `fontColor` と `backgroundColor` は **各々独立に判断** する：
  - 指定されているプロパティのみ、そのチャンネルの値を `InvertColor` で反転して `:hover` / `.active` のオーバーライドを出力する。
  - 指定されていないプロパティは反転対象にせず、TST の既定ハイライト挙動をそのまま活かす。
- 反転は各 RGB チャンネルごとに 255 − n を行う。`#rgb` 表記の場合は内部で `#rrggbb` へ正規化してから反転する。

### 6.3 add-tab-state（タブへのクラス付与）

```javascript
// 旧クラスをすべて除去してから新クラスを付与
await browser.runtime.sendMessage(TMS_COMMON.Const.TST_ID, {
    type:  'remove-tab-state',
    tabs:  [tabId],
    state: /* 現在付いている tm-rule-* クラス名 */
});
await browser.runtime.sendMessage(TMS_COMMON.Const.TST_ID, {
    type:  'add-tab-state',
    tabs:  [tabId],
    state: TMS_BACKGROUND.Rules.MakeClassName(matchedIndex)
});
```

マッチするルールがない場合は remove-tab-state のみ実行する。

### 6.4 TST ready イベント対応

TST が再起動・再ロードされた場合 `ready` イベントが届く。
`browser.runtime.onMessageExternal` で受信したら `TMS_BACKGROUND.Init()` を再実行する。

## 7. ルールマッチングロジック

```
MatchRule(url, rules):
  for i = 0 to rules.length - 1:
    rule = rules[i]
    if rule.patternType === 'prefix':
      if url.startsWith(rule.pattern) → return { rule, index: i }
    if rule.patternType === 'regexp':
      try:
        if new RegExp(rule.pattern).test(url) → return { rule, index: i }
      catch:
        skip（不正な正規表現は無視）
  return null
```

- 優先順位は配列インデックス順（0 = 最高優先）
- 最初にマッチした1件のみ適用（複数ルールの重ね掛けは行わない）

**Phase 7 仕様に伴う主要な変更点**
- 独立した「保存」ボタンは廃止。登録・更新・削除・並び替えの各操作で即時 `storage.sync` へ反映する
- 主ボタン名称はモードに応じて「新規登録 ／ 更新」に切り替わる
- 主ボタンの隣に「キャンセル」ボタン（ネガティブ配色）を配置
- ルール一覧の各行に「編集」ボタンを配置（更新モードへの遷移起点）
- 更新モード中は対象行をハイライト（`tm-rule-row-editing`）して視覚的に示す

**Phase 8 仕様に伴う主要な変更点**
- ヘッダー右側にテーマ切替トグル（☀ライト [ switch ] 🌙ダーク）を配置
- ライト／ダークの切替はチェックボックスの ON/OFF で即反映（ON=ダーク、OFF=ライト）
- テーマ設定は `storage.local.theme` に永続化（既定＝ダーク）
- 配色はすべて CSS カスタムプロパティ（`--tm-*`）経由で指定し、`:root` がダーク、`body.tm-theme-light` でライトへ上書き

### 8.2 カラーピッカー連動仕様

- テキストボックスに `#rrggbb` 形式で入力するとカラーピッカーの色が更新される
- カラーピッカーで色を選択するとテキストボックスが `#rrggbb` 形式で更新される
- テキストボックスがブランクの場合はカラーピッカーをデフォルト色（`#ffffff`）で初期化するが、保存値はブランクのまま
- テキストボックスの形式が不正な場合は赤枠でエラー表示

| 削除ボタン | class=`tm-btn-delete` | 各行に配置 |

### 8.4 バリデーション仕様

| 入力 | バリデーション | エラー条件 | 挙動 |
|------|----------------|------------|------|
| URLパターン | 必須チェック | ブランク | ブロック（登録／更新を行わない） |
| URLパターン（正規表現時） | `new RegExp(pattern)` を try-catch | 例外発生時 | ブロック |
| フォント色 | 形式チェック | ブランク以外かつ `^#[0-9a-fA-F]{3}(?:[0-9a-fA-F]{3})?$` 不一致 | ブロック |
| 背景色 | 形式チェック | 同上 | ブロック |
| 全スタイル項目 | 有効性チェック | フォント・フォント色・背景色がすべてブランク | ブロック（Phase 7 仕様で警告→エラーに変更） |

### 8.5 D&D による並び替え仕様

- ルール行に `draggable="true"` を付与
- `dragstart` でドラッグ元のインデックスを `TMS_OPTIONS.State.dragSrcIndex` に保持
- `dragover` で `preventDefault()` してドロップ許可
- `drop` でインデックスを交換し `TMS_OPTIONS.UI.RenderRuleList()` を呼び出し再描画
- ドロップ完了時点で即時 `storage.sync` に反映する（Phase 7 仕様）
- 更新モード中に対象行が swap に関与した場合は `State.editingIndex` を追従して更新する

### 8.6 編集モード／キャンセル仕様

**モード遷移**

| イベント | 遷移 | 付随処理 |
|----------|------|----------|
| ルール行の「編集」ボタンクリック | add → edit | フォームに対象ルールの値を反映、`editingSnapshot` に原値を記録、対象行をハイライト、主ボタン名を「更新」、見出しを「ルール更新」へ切替 |
| 更新モードで主ボタンクリック（バリデーション通過） | edit → add | 対象ルールを差替、即時保存、フォームクリア、モードラベルを追加モードへ戻す |
| 更新対象行そのものの「削除」ボタンクリック | edit → add | 対象ルールを削除、即時保存、フォームクリア、モードラベルを追加モードへ戻す |
| ブラウザ再読み込み（F5） | → add | ページ再読込のため初期状態（追加モード）で立ち上がる |

**キャンセルボタンの挙動**

| 現在モード | 動作 |
|------------|------|
| 追加モード | フォーム入力欄を初期状態（`ClearForm`）へ戻す |
| 更新モード | フォーム入力欄を `editingSnapshot`（編集開始時の値）へ復元する。モードは維持する |

**更新モード中の整合性確保**

- 更新対象より前の行を削除した場合 → `editingIndex` を 1 つ前へシフト
- 更新対象行そのものを削除した場合 → 追加モードへ戻し、フォームをクリア
- D&D で更新対象行が swap に関与した場合 → `editingIndex` を追従
- バリデーションは追加モードと更新モードで同一ルールを適用する（id は更新時に保持される）

### 8.7 テーマ切替仕様（Phase 8 追加）

**挙動**

- ヘッダー右側のトグル（☀ライト [ switch ] 🌙ダーク）で切替える
- チェック ON = ダークテーマ、OFF = ライトテーマ
- `change` 発火時に即 `storage.local.theme` へ保存し、`body.tm-theme-light` クラスを ON/OFF する
- オプションページ起動時は `storage.local.theme` を読み込み、他の UI 構築より前に `body` クラスへ反映することで描画フラッシュを最小化する
- 未保存（初回起動時）は既定でダークテーマ。これにより初回読込のホワイトフラッシュを抑止する

**カラートークン（CSS カスタムプロパティ）**

すべての配色は以下の変数経由で指定する。`:root` にダークの値を定義し、`body.tm-theme-light` でライトの値に上書きする。

| 変数名 | 用途 |
|--------|------|
| `--tm-bg-page` / `--tm-fg-page` | ページ全体の背景／文字色 |
| `--tm-bg-surface` / `--tm-border-surface` | セクションカードの背景／枠線 |
| `--tm-bg-table-head` / `--tm-border-table` | ルール一覧テーブルのヘッダ背景／罫線 |
| `--tm-bg-input` / `--tm-fg-input` / `--tm-border-input` | 入力フォームの背景／文字色／枠線 |
| `--tm-bg-row-editing` / `--tm-outline-editing` | 更新モード対象行のハイライト |
| `--tm-bg-row-drag-over` | D&D ドロップ対象行のハイライト |
| `--tm-btn-primary-*` | 主ボタン（新規登録／更新） |
| `--tm-btn-cancel-*` | キャンセルボタン |
| `--tm-btn-edit-*` | 編集ボタン |
| `--tm-btn-delete-*` | 削除ボタン |
| `--tm-invalid-border` / `--tm-invalid-bg` | バリデーションエラー枠 |
| `--tm-msg-error` / `--tm-msg-success` | メッセージ領域の文字色 |
| `--tm-drag-handle-fg` | ≡ アイコン色 |
| `--tm-swatch-border` | カラースウォッチの枠 |

**TST サイドバー側のテーマ対応について**

本テーマ設定はオプションページのみに適用され、TST サイドバー側のタブスタイルには影響を与えない。TST サイドバー側の配色はユーザーが各ルールで明示的に指定した `fontColor` / `backgroundColor` のみが反映される（TST 自体のテーマ設定は TST 側に委ねる）。

## 9. イベントフロー

### 9.1 拡張機能起動時

```
TMS_BACKGROUND.Init()
  → TMS_BACKGROUND.Rules.Load()              storage.sync からルール取得
  → TMS_BACKGROUND.Tst.Register()            TST に register-self（CSS 注入）
  → TMS_BACKGROUND.Tst.ApplyRulesToAllTabs() 全タブに色付け
```

### 9.2 タブ作成・URL 変更・別ウィンドウ移動時

```
tabs.onCreated / tabs.onUpdated（url 変更時） / tabs.onAttached（別ウィンドウへ移動）
  → TMS_BACKGROUND.Handlers.OnTabCreated / OnTabUpdated / OnTabAttached()
  → TMS_BACKGROUND.Tst.ClearTabState(tabId)       旧クラス除去
  → TMS_BACKGROUND.Rules.MatchRule(url, rules)    ルール評価
  → マッチあり → TMS_BACKGROUND.Tst.ApplyRuleToTab(tab)
  → マッチなし → そのまま
```

※ `tabs.onAttached` は別ウィンドウへタブ移動した際に TST 側のタブ状態がリセットされるため、
移動先ウィンドウで再評価・再適用することで Phase 7 の不具合（ウィンドウ間移動でスタイル消失）を解消する。

### 9.3 ルール変更時（オプションページの即時反映）

Phase 7 仕様で独立した「保存」ボタンは廃止され、登録・更新・削除・並び替えの各操作で
ハンドラ内から `PersistRules()` を呼び出して即時 `storage.sync` へ反映する。

```
TMS_OPTIONS.Handlers.OnAddRule / OnDeleteRule / OnDrop
  → State.rules を更新
  → TMS_OPTIONS.UI.RenderRuleList()
  → TMS_OPTIONS.Handlers.PersistRules()
    → storage.sync.set({ rules })
  → storage.onChanged イベント発火
  → TMS_BACKGROUND.Handlers.OnStorageChanged()
  → TMS_BACKGROUND.Rules.Load()                   最新ルール再読み込み
  → TMS_BACKGROUND.Tst.Register()                 TST CSS を再注入
  → TMS_BACKGROUND.Tst.ApplyRulesToAllTabs()      全タブ再評価・再適用
```

補足：
- 編集ボタン（`OnEditRule`）とキャンセルボタン（`OnCancel`）はフォーム／モードの状態のみを変更するため
  `storage.sync` への書き込みは行わない。
- 主ボタン（更新モード）でバリデーション通過後の差替時のみ `PersistRules` を実行する。

### 9.4 TST 再起動時

```
browser.runtime.onMessageExternal（type: 'ready', from TST_ID）
  → TMS_BACKGROUND.Handlers.OnTstMessage()
  → TMS_BACKGROUND.Tst.Register()                 再登録・CSS 再注入
  → TMS_BACKGROUND.Tst.ApplyRulesToAllTabs()      全タブ再適用
```
